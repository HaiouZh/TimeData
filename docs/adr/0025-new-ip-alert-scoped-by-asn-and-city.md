# 0025 陌生来源提醒按「运营商(ASN)+城市」收敛，不再按精确 IP

## 状态

已采纳（2026-07-30）

## 背景

`known_ips` 表以 `(token_tier, ip)` 为主键，按**完整 IP** 判定「首见」。这在本项目的实际使用条件下不成立：

- 用户主力网络是手机流量与家宽动态 IP。运营商 CGNAT 池与 PPPoE 重拨会在「用户完全没换网络」的情况下持续更换公网地址，典型表现是前三段稳定、末段变化。
- 用户**经常开 VPN**。VPN 出口本身就是机房 IP，且同一节点会在不同连接里给出不同地址。

结果是每换一个地址就多一条告警，用户永远确认不完；而告警内容只有一串数字，没有任何可供判断「这是不是我」的信息。等于同时具备高噪音与低信息量——这类提醒最终会被整体忽略，反而不如没有。

## 决策

**一、收敛键从精确 IP 改为「ASN + 城市」，三档降级。**

| 条件 | scopeKey |
|---|---|
| 有 ASN 且有城市 | `asn:<asn>\|city:<city>` |
| 有 ASN、无城市 | `asn:<asn>` |
| 无 ASN（库缺失 / 查不到） | `net:<IPv4 的 /24 或 IPv6 的 /64>` |

城市缺失时必须退回只用 ASN，不得拼入空值——否则「未知城市」与真实城市会成为两个不同的键，噪音换一种形式回来。

**二、`known_ips` 表直接删除，换 `known_ip_scopes`（主键 `(token_tier, scope_key)`）。** SQLite 无法改主键；存量记录不含 ASN/城市、对新逻辑零贡献，用户已批准清空重开。

**三、归属地用 GeoLite2 离线库（City + ASN），服务端查询，读 mmdb 的 `zh-CN` 地名。** 库文件由用户放进挂载目录，不进镜像。

**四、缺库必须降级而非报错**：`lookupGeo` 恒返回 `null`、收敛退回网段前缀、界面显示「位置未知」，服务照常工作。这让本地开发与 CI 不必携带 80MB 二进制。

## 取舍

**这个决策主动降低了告警灵敏度。** 若 `AUTH_TOKEN` 泄露，且攻击者恰好从用户用过的同一运营商/机房、同一城市发起访问（例如同一家 VPS 厂商的另一台机器），将**不再触发告警**。

接受的理由：

- 本仓是单人自托管、非 SaaS（见 `AGENTS.md`「审查尺度」）。
- 原设计已明确「只提醒不拦截」，真正的防线是限流与令牌本身，此提醒从来不是访问控制。
- 高噪音提醒的实际安全价值是负的——它训练用户忽略告警。降低灵敏度换回「用户真的会看」，净收益为正。

**归属地是推测，不是定位。** 国家级准确率高，但城市级对家宽与手机流量常落到省会或邻市；对 VPN 与云机房 IP，返回的是 IP 段的注册地而非机器实际位置。界面已就此加免责声明，不可作为安全证据。

## 备选与否决

- **按纯 ASN 收敛**：噪音压得更干净（VPN 换节点 IP 也不报），但灵敏度更低。用户选了更紧的一档。
- **按 `/24` 收敛、不引入归属地库**：零依赖，但运营商 NAT 池经常跨 /24，只能压掉一部分噪音，且解决不了「看不懂是谁」。
- **ip2region 替代 GeoLite2**：国内 IP 有中文省市且体积小，但国外 IP 只到国家级、拿不到 ASN——用户开 VPN 时正好废在关键处。
- **在线归属地 API**：服务端要把来源 IP 外发给第三方，且有频率限制与可用性依赖。
- **GeoLite2-City 进镜像**：镜像 +80MB，每次 Watchtower 部署多传一次。
