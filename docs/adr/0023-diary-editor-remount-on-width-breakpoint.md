# 0023 日记编辑器跨宽窄断点重挂、丢撤销栈，知情不修

## 状态

已采纳（2026-07-26）

## 背景

日记页按 1024px 断点切换两种布局：宽屏走左右分栏（`ResizableSplit`，编辑器在左、参考栏在右），窄屏只渲染编辑器。判定来自 `useIsWideScreen`（`lib/useIsWideScreen.ts`，`matchMedia("(min-width: 1024px)")`）。

渲染写法是同一位置的三元：`wide ? <ResizableSplit left={editor} …/> : editor`（`DiaryPage.tsx`）。React 按「位置 + 元素类型」协调，断点跨越时这个位置的类型从 `ResizableSplit` 变成编辑器自身（或反向），整棵子树被卸载重挂，其中的 `textarea` 是新建的 DOM 节点。

后果：**正文不丢**——它存在页面级 state 里，重挂后照常回填；丢的是挂在 DOM 节点上的那些东西：**浏览器原生撤销栈（Ctrl+Z 撤不回去）、焦点、滚动位置、输入法未上屏的字**。

触发面只在宽窄屏会变的设备上：桌面拖窗口跨过 1024px、iPad 转屏或分屏、开关 DevTools。**手机与 APK 恒为窄屏，永不触发。**

候选修法只有一条像样的：给 `ResizableSplit` 加「单列模式」，让窄屏也走同一个组件类型，位置与类型都不再变，React 就不会重挂。

## 决策

**不修。**

理由是风险不对称。单列模式要改的是**窄屏**的 DOM 结构，而日记编辑器撑满高度依赖整条 flex 链——祖先链上任何一层的 `min-h-0` / `flex-1` 少一个，编辑区就会塌或溢出。这类布局问题 **jsdom 测不出来**（无布局引擎），自动化门禁对它是盲的，只能靠真机逐台验收。

而窄屏正是 APK 的**唯一**场景。所以这笔交易是：拿「APK 主界面可能塌布局、且自动化验不出」去换「桌面偶尔拖窗口丢一次撤销记录」。代价面远大于收益面。

## 后果

- 桌面用户跨断点调整窗口大小时，撤销栈、焦点、滚动位置、IME 未上屏字会静默丢失，**正文安全**。这是已知行为，不当 bug 处理。
- 该缺陷对移动端与 APK 不成立，不进真机验收清单。
- 若将来因别的需求必须给 `ResizableSplit` 加单列模式，重挂问题会顺带消失；届时改动必须配真机验收，不能只靠 jsdom 门禁放行。
- 反向约束：其他页面若照搬 `wide ? <Split/> : bare` 这个三元写法，会继承同一缺陷。承载文本输入的页面尤其要留意——重挂丢的是输入态。
