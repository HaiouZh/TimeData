# 0026 项目与标签共用一组 tint token，类型区分靠形状不靠颜色

## 状态

已采纳（2026-07-30）

## 背景

待办页有两处「用户内容身份色」：项目名 chip（`ProjectNameChip`）的圆点写死 `bg-ok`（#34d399，所有项目同一个绿）；标签 chip（`TaskRow`）的圆点走 `tagColor()` 的 12 色 hash 色板。

要让项目「各有其色」，直接给项目圆点上色会当场撞上一个既存事实：两者用的是**同一个** `META_CHIP_CLASS` 灰胶囊 + **同一个** `h-1.5 w-1.5 rounded-full` 圆点，且在同一行 meta 区并排渲染。项目点之所以能被认出来，唯一依据是「它是全场唯一的绿」——一上色这个依据即消失，只剩标签的 `#` 前缀可读。

同时 `tagColor()` 那套自身有三处不成立：

1. **色板明度与用法错配。** `TAG_PALETTE` 12 色明度 25–30%，是按 `TagFilterPanel` 选中态「填充胶囊背景 + `--color-page` 深色字」调的。`TaskRow` 拿同一组色画 6px 圆点、铺在 `#1b2336` 的胶囊底上，对比度不足以看见——那个圆点不传递任何信息。
2. **填充态本身也不可读。** `TagFilterPanel` 选中态 `backgroundColor: #2F4858` 配 `color: var(--color-page)`（#0e1320），对比度 **1.93:1**，远低于 4.5:1 门槛；旧色板 12 支在这个场景是 1.9–3.1（均值 2.6），**没有一支达标**。两种用法都不成立，这组色没有一处是对的。
3. **名义 12 色，可辨 4–5 档。** `#3D5A80` / `#445A7A` / `#54667A` / `#48506B` / `#4C5C68` 是肉眼分不出的蓝灰。`turnTags.test.ts` 只钉「不塌成单色」，钉不住「人能分辨」。

## 决策

**一、一组共用 token `--color-tint-1..9`，项目与标签同源取色。** 两者都是「用户内容的身份色」，是同一件事；分两套会得到两倍的 token 各自调和，且随时间漂成两种调性。

**选色的约束是对比度，口径是 WCAG 相对亮度，不是 HSL 明度。** 三个场景各有门槛：6px 圆点属非文本图形（WCAG 1.4.11，3:1）、`#` 是 caption 档小字（1.4.3，4.5:1）、填充态是 `--color-page` 深字压彩底（4.5:1）。实测四个场景全部达标、最差支仍有 1.4 倍余量（圆点对 surface ≥5.6、`#` 对 surface-elevated ≥5.2、填充态对 page ≥6.2）；旧色板在同样四个场景是 **12 支全部不达标**（最高 3.14）。

两个口径必须分清，否则因果会讲反：这组色的 HSL 明度跨 50–76%，而 HSL 明度最高的几支（紫/粉，76%）恰恰是相对亮度最低、对比度最差的几支（6.2:1）——两者近乎负相关。**决定「看不看得见」的是相对亮度**。旧色板的病因同样应这样表述：它的相对亮度太低（12 支全部 < 3.2:1），而不是「HSL 明度档不对」。

色相**尽量**避开 `--color-accent`（实测 213°）、`--color-ok`（158°）、`--color-warn`（43°）、`--color-danger`（0°）四个已占用值——小圆点撞上唯一动作色会被当成可点元素，撞上状态色会被读成告警。**「尽量」是实话不是修饰**：四个禁区各留 ±20° 缓冲即吃掉 160° 色相环，剩下 200° 放 12 支平均间隙不到 17°，与「支间彼此可辨」直接冲突。两全做不到——最终砍到 9 支，取舍见下。

具体色值与支数都不在文档里拍板：色板挂进 `/dev/styleguide` 预览页，在真实暗底与真实尺寸（6px 圆点、caption 档 `#`、筛选面板填充态三种形态并列）上人工验收后定稿。初版 12 支正是在这一步被否的（见取舍）。理由与全站视觉一致性同一条——不做像素快照，靠 styleguide 人工验收。

**二、类型区分交给形状，不交给颜色。** 圆点 = 项目，`#` = 标签。标签那个不可见的 6px 圆点删除，改为给 `#` 字符本身着色：`#` 是既有的、不需学习的类型标记，且作为字形其面积远大于 6px 圆点，同一个色终于读得出。颜色由此只承担一件事——同类型内区分个体。

圆点因此成为项目的专属形状，出现在组外行的项目名 chip 与项目区组卡片标题行两处（同色，构成「点↔点」的同一项目认同）。组卡片不另加左侧色条：同一张卡片上两个颜色信号是同一件事的两种说法，与项目区既有的「行内绿竖条与项目名 chip 排他」是同一条裁剪规则。

**三、都不存储，但项目避撞、标签不避撞。** 共享内核 `lib/contentTint.ts`：

- **标签** `contentTint(标签名)` = 哈希取模，允许撞色。一条任务上的标签集合各不相同、同屏可见的标签数远超色板宽度，「全局互不同色」既不可达也无意义——标签的主标识是它的名字。
- **项目** `assignProjectTints(按 createdAt 升序的 goalId 列表)` = **集合内避撞**。首选位仍由 `goalId` 哈希决定（所以颜色散布在整个色板上，不是从 `tint-1` 依次发号——后者会让「只有三个项目」时永远看不到色板后半截），首选被占才顺移到下一个空位。≤9 个项目时保证互不相同。

**纯哈希对项目不够，是算完概率才发现的**：按生日问题，4 个项目就有 54% 概率存在两个同色、5 个 74%、6 个 89%。原先记的「超过 12 个项目才必然撞色」字面没错，却掩盖了这个分布——而项目色的全部意义就是「一眼认出这条属于哪个项目」，一半概率认错等于没做。

分配**基于全部 active project**（在 `listTasks` 里算、随 `TodoBuckets` 下发），不能按 `buckets.projects`：后者是「有可解析成员的组」，某项目成员全部完成后它离开显示集合、释放色位，会让别的项目跟着换色。组件因此不自己取色——`ProjectChip` 带 `tint` 字段、组卡片收 `projectTints`，因为避撞只有拿着全集才算得出。

排序键取 `createdAt` 而非 id 字典序：新建项目排末尾，只挤到自己、不动已有分配。

返回 `var(--color-tint-N)` 字符串而非 Tailwind 类名：`bare-raw-color` 规则只拦裸 hex/rgb/hsl/oklch 字面量，`var()` 合规；且 `TaskRow` 标签点与 `TagFilterPanel` 三态本就是 inline style，沿用即零形态变更。走 utilities 则须为 `bg-` / `text-` / `border-` 各列一整套类名字面量——Tailwind 4 扫不到动态拼接的类名，那些字面量换不到任何东西。

**四、12 个裸 hex 退出 allowlist。** `TAG_PALETTE` 连同它占的 12 项 `user-content-color` 例外一并删除，`design-language-allowlist.json` 从 54 项降到 42 项。新代码零裸色、零新增例外。

## 取舍

**项目与标签之间仍会撞色，接受。** 避撞只在项目集合内部生效，跨类型不避。共用 9 色、一行最多显示 3 个标签（`TaskRow` 的 `slice(0, 3)`），任一标签与项目同色的概率是 11% / 21% / 30%（1 / 2 / 3 个标签）——约每三条多标签任务遇上一次，比 12 支时（8.3/16/23%）更频繁，这是砍支数换辨识度的代价。它不产生歧义：类型判定已由形状闭环，撞色只留下「它们碰巧同色」这一闪念，不导致误读归属、也不导致误操作。

否决了「给标签 `#` 降一档饱和」这种第二重区分：`#` 是 caption 档小字形，提亮色板的全部目的就是让它可读，再压一档等于把刚修好的收益抚平一半——拿一个「真读不清」去换一个「弱杂念」。

**项目色不可手改，且删除 / 归档项目会让个别项目换色。** 后者是避撞的固有代价：被删项目占着的首选位释放后，当初因它而被顺移的那些项目会拿回自己的首选位。换来的是「≤9 个项目时一定互不相同」。**这不是 bug**，已由 `contentTint.ts` 的注释与 `contentTint.test.ts` 的用例钉住，免得日后被当异常「修」掉。超过 9 个项目时超出的部分回落到各自首选位，撞色不可避免（鸽笼原理）。

加 `color` 字段让用户手选能同时解决这两条，但命中 schema 停手边界（`shared` zod + SQLite 列 + 同步域 + Dexie + cli + 夹具全对齐）外加一套选色 UI，代价是本方案的数倍。

**存量标签颜色全部改变。** 色板换了，不可逆也不该逆——旧色本就调在错误的明度档，其中 5 支还互相分不出。

**`--color-data-*` 与 `--color-tint-*` 是两层不同的东西、各自独立演进**，前者服务图表数据序列（固定 6 色，不外溢 UI chrome）要求跨图表稳定可比，后者服务用户内容身份要求个体可分辨。两层不合并成一个 token 集；但**不承诺色值不重合**——`tint-4` 与 `--color-data-teal` 逐字节相同（`#2dd4bf`）。同一个 hex 出现在两层是允许的，因为两层的消费场景不同屏。初版还有一处 `tint-8` 与 `--color-data-purple`（同时也是 `--galaxy-edge`、且在 tracks 页承载「agent 在跑」语义）相同，随砍支一并消失。

**色板宽度定在 9 支，是「彼此可辨」压过「少撞色」的结果。** 初版 12 支在 `/dev/styleguide` 上被否：四个禁区吃掉 160° 色相环后，12 支的相邻间隙只剩 10–15°，实测紫区四支里最近一对 CIEDE2000 仅 **5.51**（234–292° 塞了 4 支），青区三支里 `tint-5`↔`tint-6` 色相只差 10°——6px 圆点上分不出，等于名义 12 色、可辨 8–9 色。砍掉紫罗兰、亮紫、青三支后：任意两支色相 ≥24°，最近一对色差 13.1，全部靠色相区分而不靠明暗。

初版另有一支 `#fb7185` 距 `--color-danger` 仅色差 5.83（色相差 9°）——项目圆点与「危险/错误」感知同色，正是决策一列为禁止的情形，已换成浅一档的 `#fda4af`（色差 13.4，色相仍在 353°，整体观感不变）。

**残留最近项**：`tint-3`（绿 142°）距 `--color-ok`（158°）色差 7.28，是九支里离状态色最近的一支。它与 `ok` 不会同屏指向同一条任务（项目 chip 与绿竖条排他，见 [todo/project-zone](../evergreen/todo/project-zone.md)），但仍留待真机长期使用后复核。

## 适用域

**适用**：`Task.tags`（任务行、详情抽屉、筛选面板）与 `Goal(kind="project")`（待办页项目区的组卡片标题与组外 chip）。

**不适用、且不需要适用**：goals 页用文字徽章区分「项目 / 主题」，不用颜色表达身份；stats 的标签与项目维度按 open/done 堆叠着色，个体身份走 Y 轴文字，上 tint 反而撞上本文「两层各自独立」的边界；`TrackStep.tags` 是另一个实体的标签（充当看板信号，不与 `Task.tags` 共享命名空间），其胶囊与任务标签同形但不同源。

## 备选与否决

- **形状分工（项目圆点、标签方块）**：同样能闭环类型区分，但要新造一种标记形状，而 `#` 是已经在那儿、用户不用学的类型标记。
- **一行只允许一处彩色（标签点改灰或撤掉不着色）**：最安静，但标签在任务行失去颜色身份，而筛选面板里仍有色，同一个标签两处不一致。
- **色域分家（项目暖调、标签冷调）**：两边色板各砍一半，项目只剩 5 支、撞色率翻倍；且「暖/冷」是靠学习才读出的约定，不是一眼分辨。
- **项目与标签各一套色板**：见决策一——22 个 token 两处调和，必然漂成两种调性，而「避开对方全部色相」实际做不到。
- **按创建顺序依次发色（tint-1、tint-2…）**：同样保证不撞色且无需存字段，但只有三个项目时永远只看到色板前三支、后半截用不到；且删掉一个早期项目会让其后**所有**项目集体位移换色，而避撞分配只影响「首选位被它占着」的那几个。
- **Goal 加 `color` 字段、创建时随机**：可手改色，但命中 schema 停手边界，见取舍。
