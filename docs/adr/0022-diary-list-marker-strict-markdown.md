# 0022 日记列表识别钉死为 Markdown 标准，否决放宽与提示机制

## 状态

已采纳（2026-07-27）

## 背景

日记编辑器的三个自定义键位（回车续号 / Tab 缩进 / Ctrl+K）都依赖 `listModel.ts:ITEM_RE` 判定"这一行是不是有序列表项"。真机使用中反复出现同一类反馈："回车后吐出一行没有序号的行，接着按 Tab 焦点跳到分栏拖拽线"。排查确认根因是**形近写法**：中文输入法下极易写出全角数字（`１`）、中文句号（`1。`）、全角空格缩进 / gap，或编号后不加空格（`1.二级`）——这些行肉眼与标准列表几乎无法区分，但不满足 Markdown 的 marker 格式，整行按普通文本处理，于是回车是原生换行、Tab 认不出该行。

针对这个落差先后出现三条路线：

1. **识别放宽 + 写回规范成半角**：marker 四个位置都认全角，被改写的块输出时规范成标准形态。曾以 `62b38f54` 合入（含 `Number("１") === NaN` 防护、等宽缩进替换、小数护栏等一整套配套）。同思路还延伸出"gap 允许为空 + 小数护栏"的无空格放宽（未合入）。
2. **提示机制**：识别保持标准，在形近行上回车时弹提示条（可带"一键补空格"按钮），或做镜像高亮层实时标红伪 marker。
3. **什么都不做**：标准之外一律普通文本，编辑器不改写、不提示。

## 决策

采纳路线 3，**识别口径钉死为 Markdown 标准**：`ITEM_RE = /^([ \t]*)(\d{1,9})\.([ \t]+)(.*)$/`——半角数字 + 半角句点 + 至少一个半角空白。路线 1 已回退（`890dbf64` revert `62b38f54`），路线 2 不实施。

否决理由：

- **编辑器要纯粹、符合标准**。放宽识别会造成"编辑器认、渲染器不认"的两套行为——全角 marker 在 CommonMark / Obsidian 里根本不构成列表，同一份 vault 文件在两处语义不一致。
- **自动改写用户字节有误伤面**：写回规范化必须整块改写，`1.5小时` 这类小数、`2026.国庆` 这类"数字.文字"写法都在误伤边缘，护栏越堆越多。
- **提示补丁会越积越多**，逐渐堆成屎山，且提示本身会阻碍正常编辑。

形近写法的实际缓解不靠识别层，靠**正常路径不产生它们**：空白日记预填 `1. `、回车自动续号——序号由编辑器生成，天然合规；用户手写出格式不对的行的机会本来就少。

## 后果

- "写了 `1.二级` / `１. 二级` 回车没续号"是**符合预期的行为，不是 bug**——后续同类反馈不再做放宽救援，也不加提示。
- 编辑器行为与 Obsidian / CommonMark 完全一致，vault 文件语义唯一。
- 手写形近 marker 无自动纠正；用户需要自己把它改成标准写法，编辑器才接管续号与缩进。
- `listModel.ts` 保持单一简单正则，无规范化 / 半角化 / 护栏配套的维护负担。
