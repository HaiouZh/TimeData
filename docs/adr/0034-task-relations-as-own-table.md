# 0034. 前置关系独立成表，父子仍留在 Task.parentId

- 日期：2026-08-16
- 状态：已接受
- 关系：修正 todo-track-converge metaspec 的拍板③措辞（原文是「父子与前置合并成一张关系表」）

## 背景

在此之前，「A 挡着 B」这种前置关系存在 `Goal.prerequisites` 这个 JSON 字段里，是目标的一个属性——
只有在目标详情页的星图上才连得出来、看得见。待办页对它一无所知，一条被前置挡住的任务照常出现在
「今天」，用户点开发现做不了。

而一层父子关系走的是另一套：`Task.parentId`。

todo-track-converge 的路线图（2026-08-14 拍板）写的是「父子与前置合并成一张关系表」——把两种关系
统一成一个模型。阶段3 实施时只做了一半，这条 ADR 记录为什么。

## 决策

**前置边独立成表 `task_relations`**，一行一条有向边，四元复合主键
`(blocker_kind, blocker_id, blocked_kind, blocked_id)`，两端各自可以是任务或轨道。

**父子关系不搬，仍然是 `Task.parentId`。**

### 为什么前置必须离开 Goal.prerequisites

不是为了「模型更干净」，是同步会丢数据。

前置是多对多且两端异质（任务能被轨道挡）。挂在实体字段上，无论挂 `Goal.prerequisites` 还是
`Task.blockedBy: string[]`，一条边的增删都表现为**对某一行的整行写**。而同步是 LWW：两台设备各连
一条边、各推一次整行，后到的整行覆盖先到的，先连的那条边静默消失——没有冲突提示，用户不会知道。

独立成表后每条边是自己的同步单元。两台设备各连各的边，推的是两条不同记录，互不覆盖。

边的语义还让 LWW 在这里格外安全：一条边要么在要么不在，没有中间字段可以被部分覆盖。

### 为什么父子不跟着搬

三条，每条单独都不足以否决，合起来足够：

1. **父子恒为一层**，而通用关系表表达的是任意图。搬进去之后「一层」从结构保证降级为需要额外校验的
   约定——校验写在哪、谁来跑、同步来的数据谁拦，全是新问题。（现在这条约束也不是滴水不漏：normal
   sync 路径上没有深度校验，只有 force-push 拦，已登记 backlog。但那是一条缝，不是没有墙。）
2. **父子承载排序**。`child.sortOrder` 在父作用域内有意义，父子关系与顺序是绑在一起的；通用关系表
   里没有「第几个」这个概念，要么再加一列、要么排序无处安放。
3. **父子承载级联删除**。删父连带删子是一次事务内的整体动作，`deleteTaskCascade` 靠 `parentId`
   一次查全。搬进关系表后同样的动作要先查边、再解引用、再删——多一层间接，且那层间接可能有悬空边。

**子任务的松绑不需要合并模型就能做到**：阶段3 逐条解除了子任务身上的守卫（能定日期、抓手头、升格
轨道、打标签、归项目、有自己的前置），`parentId` 的结构一个字没动。合并模型的原始动机——「让子任务
不再是二等公民」——用便宜得多的办法达成了。

## 后果

**旧字段被清空，且禁止回写。** `Goal.prerequisites` 由一次性迁移搬空（阶段3 唯一不可逆的一步，配
本地快照与设置页的重建按钮）。读取侧留了一个兼容层 `hydrateGoalPrerequisites`，每次把边填回内存中的
goal 对象，让阶段2 就写好的目标页判定逻辑零改动；**写入侧一律不碰这个字段**，由机器闸
`scripts/check-legacy-prerequisites.mjs`（`pnpm check:prereq`）盯着——任何往 `prerequisites:` 写非空
字面量的代码都会让门禁红。

立这道闸的原因是踩过：写入侧是「读—改—写」的形态（连边时整包回写），而它读到的 goal 已经过 hydrate，
于是任何一次连边都会把新表的边整包倒灌回旧字段，走出「清空 → 连边 → 倒灌 → 下次启动又搬又清」的
循环，中间任何一次断边都会复活成僵尸边。

**两个模型并存的代价**：以后想加「子任务也是一种关系」的功能时，要同时改两处。这是明知的取舍——
比起「一张表管所有关系」带来的一层校验、排序无处安放、级联删除多一跳，两个模型并存更便宜。

**混合版本期有已知缺口**：老客户端删任务只推 `tasks/delete`、不知道关系表存在，新客户端拉到后关系表
里会残留悬空边（显示为「（已删除）」占位）；反过来老客户端的陈旧旧字段副本被推上来时，补迁移会让已删
的边复活。两条都在全部设备升级后自动关闭，细节见 [前置关系表 §7](../evergreen/todo/task-relations.md)。
