# 0028 中国归属地改用内置 ip2region 段表，收敛键加中国省市档

## 状态

已采纳（2026-08-01）

## 背景

ADR 0025 之后的实测发现：**GeoLite2 免费库对中国运营商段没有 city 级数据，是结构性缺失而非 bug**。以用户主力网络（中国移动/联通/电信的家宽与手机流量段）为例，City 库要么查不到城市、要么落成国家级——换最新版 mmdb 也一样，因为 MaxMind 免费版本身不含中国运营商段的城市粒度。结果是「中国 IP 显示中国 · China Mobile communications corporation」，地名信息几乎为零，收敛键则全部掉进最宽的 `asn:<n>` 档（一个 ASN 等于一个运营商在国内的全部地址空间）。

本仓的告警收敛逻辑（`ipScope.ts`）与展示（请求日志、陌生来源提醒）都依赖城市级粒度。对个人用户，**中国段恰恰是归属地信息最重要的部分**——所以单独修这一块，不碰国外路径。

## 决策

**一、中国归属地改用内置的 ip2region 段表（约 750KB，随镜像发布）。**

离线脚本 `scripts/gen-china-geo.mjs` 把 [ip2region](https://github.com/lionsoul2014/ip2region) 原始数据（`ipv4_source.txt`，Apache-2.0）中的中国段抽出、归一（省名混写、街道级脏数据、英文城市名、拼写错误）、压成自定义二进制表 `packages/server/assets/china-geo.bin`（大端；magic `TDCN`；区间二分 + 地区组合池化），提交进仓库随镜像发布。运行时 `lookupGeo` 先查这张表：

- **命中即中国**：`country: "中国"`、`region`（省）、`city`（市）、运营商（`asnOrg`）全取自带数据；ASN 号仍来自 GeoLite2-ASN（收敛键要数字 ASN，中国表不提供）。
- **未命中原样走 GeoLite2**——国外路径一行不改。

**二、收敛键中国走 `asn:<n>|cn:<省>:<市>`，缺市退 `asn:<n>|cn:<省>`，皆无退 `asn:<n>`。**

这是对 ADR 0025「城市那一档的键用 geoname_id 而非本地化城市名」的**部分修订**，只涉及中国段：

- 0025 否决地名做键的两个理由在中国段不成立。「同名不同国碰撞」不成立：键带 `cn:` 前缀且只用于中国，不存在第二个使用该前缀的数据源。「换库后地名漂移导致已确认范围重报」在中国段是一次性切换成本而非持续风险：归一后的中文省市名来自**固定版本的静态表**（随仓库走，不是每月更新的外部库），跨版本稳定。
- GeoLite2 的 `geoname_id` 在中国段没有对应物（它压根没有 city 数据），所以中国档用不了数字 ID——只有中文省市名可用。
- 省市两档 vs 0025 的城市一档：ip2region 香港段等 5802 个段只有省没有市，缺了省级档它们会全部掉进最宽的 `asn:<n>` 档。

两套键前缀不同（`cn:` vs `geo:`）因而不碰撞；`asn:9808|cn:江苏省:南京市` 与 `asn:9808|geo:1796236` 永远指向不同判定。

**三、省市对外拼成一个展示串，沿用现有 `city` 字段，不加列。**

`known_ip_scopes.city` 与请求日志里的地名纯粹用于展示（收敛判定走独立的 `scope_key`），不值得为它开 schema 变更。新导出 `geoDisplayCity(geo)`：省是市的前缀时只出一个（直辖市归一后省=北京、市=北京市，不去重会打出「北京 北京市」），无省时原样返回 GeoLite2 城市名。代价是 `city` 字段语义变成「地区显示串」——日后要按省筛选需回头加列。

**四、数据在本机离线加工后进仓库，不像 GeoLite2 那样定时拉取。**

ip2region 原始数据必须先归一才能用，而那道「未知写法报错退出」的闸（防止重跑时悄悄引入新收敛键）必须有人看着；搬到线上变成「半夜报错，服务该降级还是用旧数据」。且上游约一年才更新一次。生成脚本与重新生成方法见 `packages/server/assets/README.md`。

**五、GeoLite2 继续每月自动更新（可选 `geoipupdate` 容器，profile `geoip`），更新后重启容器生效。**

`geoip.ts` 是进程启动时把 mmdb 读进内存、之后不重读。不做热重载：本仓发版频繁（Watchtower 常态重启），热重载是为几乎不存在的窗口付代价，且重载瞬间双份内存（70MB → 140MB）。

## 取舍

- **切换当天已确认的中国范围会重报一次**：`scope_key` 从 `asn:<n>` 变成 `asn:<n>|cn:<省>:<市>`，已确认记录对不上新键，用户需重新点一遍「知道了」。这是一次性成本。
- **ip2region 数据停在 2025-09-05**，比 GeoLite2 每月更新旧。对静态的省/市/运营商归属影响很小（新增的运营商段以月计才几条），且中国段的收敛键用的是省级/市级粒度，不敏感。
- **省/市归属是推测，不是定位**（同 ADR 0025 的免责声明），这里不再重复。
- 中国表缺文件或损坏时降级为「只有国家」，不抛错；`getGeoipReadiness()` 第三路 `chinaTable` 上报，洞察页提示条可并列显示「缺 GeoLite2」与「中国表未就绪」。老客户端不认 `chinaTable` 字段时按就绪处理，不刷假告警。

## 备选与否决

**DB-IP（本 ADR 最重要的一条）**。调研时 DB-IP 一度是首选（覆盖率 100%），铺开全部 65412 个中国段实测后否决：

- 覆盖率 100% 是覆盖的噪音。DB-IP 把中国切成 **1979 个城市名 vs ip2region 的 455 个地级市**，平均一个地级市被切成 **13.9 个名字**（`Jinrongjie (Xicheng District)` 一条就 5986 段）。
- 粒度到街道：北京被切成 201 个名字、上海 121 个，且上海混入 Washington D.C.（跨国错误数据）。
- 用它做收敛键等于「人在北京没动、换个基站就重报」——本主题要解决的正是这种噪音，不能制造更大一号的。

其他被否决的：

- **IPinfo Lite**：免费版无城市数据，直接不满足需求。
- **纯真 qqwry**：国内覆盖好但许可不明 + 停更，不适合随镜像发布。
- **GeoIP2 商业版**：$1628/年订阅，个人自托管不值。
- **ADP 0025 当时的「ip2region 替代 GeoLite2」**：那次的方案是用 ip2region **替换整个** GeoLite2——国外 IP 只到国家级、拿不到 ASN，用户开 VPN 时正好废在关键处，所以被否决。本次是**补缺不是替代**：ip2region 只负责中国段（它的强项），国外路径与 ASN 仍走 GeoLite2。否决理由针对的场景没有回来。
